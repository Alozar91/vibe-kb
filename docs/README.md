# Документация проекта vibe-kb

Все документы пишутся на русском языке. Общая терминология и решения — в [concept.md](concept.md).

| Документ | Назначение | Статус |
|---|---|---|

| [requirements.md](requirements.md) | Функциональные требования (ТЗ): REQ-ID с критериями приёмки, трассировка к исходным требованиям 1–38 | **Готов** |
| [data-model.md](data-model.md) | Модель данных: таблицы, поля, индексы, журнал статусов, ключи идемпотентности, правила миграций | **Готов** |
| [api-spec.md](api-spec.md) | Контракт REST/RAG API: эндпоинты, ошибки, `Idempotency-Key`; MCP-инструменты | **Готов** |
| [auth-setup.md](auth-setup.md) | Настройка Keycloak (realm, клиенты, LDAP, Kerberos/SPNEGO), требования к AD-администраторам, жизненный цикл пользователей | **Готов** |
| [code-standards.md](code-standards.md) | Правила построения кода: структура backend/frontend, слои, транзакции (UoW), sync-first, качество | **Принят (v1.0)** |
| deployment.md | Dev-стенд (docker-compose), env, TLS приёмочного стенда, бэкапы и сверки | Запланирован |

| testing.md | Стратегия тестирования: testcontainers, корпус-фикстуры (мультиформат, ru/en), тестовый Kerberos, нагрузочный sanity | Запланирован |
| adr/ | Архитектурные решения (ADR): pgvector vs Qdrant, очередь задач, UI-кит, контракт чанкеров, скачивание через API | Запланирован |

## Правила

- Изменения концепции — правками по тексту; новые функциональные требования фиксируются в `requirements.md` и в матрице соответствия (§17 концепции).
- Ключевые архитектурные решения оформляются ADR (номер, контекст, решение, последствия).
