# Стратегия тестирования

- **Статус:** рабочий документ (v0.1, 2026-11-20)
- **Основа:** `code-standards.md` (качество), `requirements.md` (критерии приёмки REQ = основа тест-кейсов), §18 концепции (CI).

---

## 1. Принципы

1. **Критерий приёмки REQ = тест-кейс.** Каждое требование из `requirements.md` имеет проверяемый критерий — он превращается в автотест со ссылкой на REQ-ID в имени (`test_status_transitions_reject_draft_to_confirmed[СТАТ-2]`).
2. **Сервисы тестируются без HTTP**: юнит/интеграционные тесты вызывают сервисы напрямую (sync-first делает это простым — `code-standards.md` §2.3).
3. **Инфраструктура — настоящая, не моки**: Postgres+pgvector, Valkey, Silo поднимаются через testcontainers. Мокируем только внешние LLM/embeddings (OpenAI-compatible — свой стаб-сервер).
4. **Детерминизм**: тесты на стандартных чанкерах фиксируют ожидаемые чанки (фиксированные параметры); тесты на эмбеддингах проверяют факт записи вектора, а не сходство текстов.

## 2. Пирамида

| Уровень | Что | Инфраструктура | Где живут |
|---|---|---|---|
| **L1. Чистая логика** | Машина состояний (СТАТ-2), разрешение прав (ПРВ-6/8), разрешение чанкера по иерархии (ЧНК-4), ключи идемпотентности (НФТ-9), валидация схем атрибутов | без БД | `tests/unit/` |
| **L2. Сервисы + репозитории** | Бизнес-операции на реальной БД: создание версий, дедупликация sha256, soft-delete, журнал статусов, выдача ролей | testcontainers: Postgres (pgvector), Valkey | `tests/integration/` |
| **L3. API** | HTTP-контракт: коды ошибок (401/403/404/409/413/423/429), Idempotency-Key-повторы, пагинация | testcontainers + httpx ASGI | `tests/api/` |
| **L4. Пайплайн** | Полный цикл файла: AV-гейт → извлечение → чанкование → эмбеддинги (стаб) → поиск; переиндексация; реконсиляция | testcontainers + стаб моделей + фикстурный корпус | `tests/pipeline/` |
| **L5. Контракт фронта** | Сгенерированные типы OpenAPI соответствуют api-spec; логика `can()`/переходов | node/vitest | `frontend/tests/` |

- Frontend (Этап 1): Vitest-юниты логики (`can()`, доступные переходы), минимальные компонентные тесты; e2e (Playwright) — не раньше Этапа 2.
- Ручная приёмка (не автоматизируем на dev): Kerberos/SSO — чек-лист `auth-setup.md` §4.

## 3. Testcontainers-набор

| Контейнер | Образ | Зачем |
|---|---|---|
| postgres | `pgvector/pgvector:pg17` | основная БД: миграции прогоняются на каждом контейнере (`alembic upgrade head` — сами тесты схемы) |
| valkey | `valkey/valkey:9` | кэш прав, брокер |

| llm-stub | свой мини-стаб (FastAPI) | OpenAI-compatible: `/embeddings`, `/chat/completions` — детерминированные ответы, счётчик вызовов (для идемпотентности) |

## 4. Фикстурный корпус (tests/fixtures/corpus)

| Файл | Что покрывает |
|---|---|
| `report_ru.pdf`, `report_en.pdf` | извлечение, FTS ru/en (ПСК-5) |
| `protocol.docx` | DOCX-экстракция, потеря структуры (§9.2.1) |
| `price.xlsx` (3 листа, формулы) | табличный чанкер, кэш формул (ЧНК-9) |
| `data.csv` (ru, `;`) | CSV-экстрактор, разделители |
| `guide.md`, `page.html` | разметко-ориентированный чанкер, HTML→PDF |
| `image.png`, `chart.svg` | `text_extracted=unsupported`, превью-правила (ПРС-2) |
| `big.bin` (~50 МБ boundary) | лимит 413 (НФТ-5) |
| `broken.pdf` | `text_extracted=failed`, документ остаётся скачиваемым (ЧНК-6) |
| `fake.txt` (реально PDF) | детекция типа по содержимому (ЧНК-7) |

Каждый файл в корпусе — с YAML-паспортом (mime, ожидаемые шаги пайплайна), чтобы тесты не хардкодили пути.

## 5. Обязательные сценарные тесты (выборка по REQ)

- **СТАТ-2**: все 7 разрешённых переходов проходят; все прочие — 409; журнал append-only (СТАТ-2 + НФТ-9).
- **СТАТ-5**: список проверяющих фиксируется при отправке; отзыв роли после отправки не мешает подтверждению.
- **ПРВ-2**: nav-only предки видны, содержимое — нет.
- **ПРВ-9**: отзыв роли мгновенно закрывает материал в поиске и RAG.
- **ВЕРС-2**: double-submit с одним Idempotency-Key → одна версия; правка без изменений → отказ.
- **ВЕРС-4**: обновление родителя не меняет детей; индикатор N<M.
- **ЧНК-4**: пример дерева Корень/B/C/D из концепции.
- **НФТ-9**: обрыв воркера на шаге `embed` → реконсиляция продолжает с него, дублей чанков нет.
- **НФТ-4**: файл до прохождения AV — 423, после — доступен.
- **ПРС-1**: скачивание пишет аудит (НФТ-1).

## 6. Flaky-политика и CI

- В CI ретраев нет: flaky-тест = дефект теста или кода — фиксируется issue, тест изолируется (mark `quarantine`) и чинится в текущем спринте.
- Время: L1–L3 < 5 мин; L4 — по тегу (полный прогон в nightly, на PR — смоук-подмножество).
- DoD (Definition of Done) фичи: код + тесты на затронутые REQ-критерии; CI зелёный; `requirements.md`/`data-model.md`/`api-spec.md` синхронизированы; аудит-события новых операций добавлены; идемпотентность изменяющих операций проверена.

## 7. Что сознательно не тестируем автотестами

- Kerberos/SPNEGO сквозь браузер (ручной чек-лист `auth-setup.md` §4).
- Реальные LLM-ответы (качество — ручная оценка на корпусе, Этап 2).
- Визуальную регрессию UI (после стабильного дизайна).
