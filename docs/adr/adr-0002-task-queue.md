# ADR-0002: Очередь задач — Valkey (broker Celery)

**Статус:** принято · **Дата:** 2026-11-20

## Контекст

Асинхронная обработка файлов (извлечение, чанкование, эмбеддинги, конвертация) и фоновые задачи (переиндексация, уведомления, реконсиляция). Нагрузка — редкие и долгие задачи, без высокого RPS.

## Решение

Брокер задач — **Valkey** (broker + result backend Celery) с задачами-«будильниками»: источник истины — PostgreSQL, задача идемпотентна, при потере брокера реконсилятор перевыставляет по состоянию БД (§13.1).

## Альтернативы

- **RabbitMQ** — честная очередь с per-message ack/DLQ/приоритетами, но лишний stateful-сервис; триггеры перехода зафиксированы (гарантии доставки, не закрываемые реконсиляцией; приоритеты; несколько независимых потребителей).
- **Kafka** — журнал событий, не очередь задач: нет нативных отложенных задач, offset-commit, тяжёлый кластер. Не рассматривается для задач; возможен позже как событийная шина между системами.

## Последствия

- (+) Один сервис на три роли (брокер, result backend, кэш прав + rate-limit); BSD-3, активная разработка (9.x).
- (+) Смена брокера — сменой конфига Celery, без правок кода.
- (−) Слабее персистентность очереди — компенсируется реконсилятором из БД (НФТ-9).
